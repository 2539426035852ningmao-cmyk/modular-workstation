### 2. Analysis of Changes

#### A. IME Composition vs. Enter Key Handling (`src/CommandPalette.tsx`)
```tsx
return <dialog ref={dialog} ... onKeyDown={e=>{
  // Leave IME Enter confirmation to the input method; only suppress dialog dismissal.
  if(composing.current||e.nativeEvent.isComposing||e.keyCode===229){if(e.key==='Escape')e.preventDefault();return;}
  if(e.altKey||e.ctrlKey||e.metaKey)return;
  if(e.key==='ArrowDown'||e.key==='ArrowUp'){e.preventDefault();if(results.length)setIndex(i=>(i+(e.key==='ArrowDown'?1:results.length-1))%results.length);}
  else if(e.key==='Enter'&&e.target===input.current){e.preventDefault();if(current)execute(current.id);}
}}>
```

1. **Chromium Engine Composition vs. Physical Windows IME**:
   - On Windows Chromium, active IME composition typically dispatches `keydown` events with `keyCode: 229` and/or `isComposing: true`.
   - When the user presses `Enter` to commit raw Latin/pinyin text directly without selecting candidate words from the IME window, the event arrives while `composing.current` / `isComposing` / `keyCode === 229` is active.
   - By **not** calling `e.preventDefault()` on `Enter` during composition, the IME engine receives the uncancelled event required to finalize and commit the text composition into the `<input>`.
   - Because of `return;`, the palette does **not** trigger `execute(current.id)`, preventing premature execution/navigation while confirming pinyin composition.

2. **Dialog Dismissal & Escape**:
   - `if (e.key === 'Escape') e.preventDefault(); return;` suppresses default native dialog cancelation while actively composing or handling IME keystrokes, ensuring pressing Escape to abort a pinyin composition sequence cancels candidate composition without dismissing the command palette modal.
   - `onCancel={e => { if (composing.current) e.preventDefault(); }}` additionally protects standard native `<dialog>` cancellation events triggered during active composition.

3. **Post-Composition Confirmation**:
   - Once composition ends (`compositionend` sets `composing.current = false`), subsequent presses of `Enter` (non-composing, `keyCode === 13`) correctly hit `else if(e.key==='Enter'&&e.target===input.current){e.preventDefault();if(current)execute(current.id);}`.
   - Native `<dialog>` contains no `<form method="dialog">`, and the only button has `type="button"`, so leaving non-composing `Enter` to `execute()` and calling `dialog.current?.close()` maintains clean focus restoration before navigation.
