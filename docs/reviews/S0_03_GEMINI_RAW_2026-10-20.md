## 二、具体发现（按严重度列出、含文件行号与最小复现）

### 1. [中危 / 依赖规范] 独立校验脚本引用了未在依赖清单声明的模块（幽灵依赖）
- **文件与行号**：
  - [`package.json`](../../package.json#L20-L29)
  - [`scripts/verify-package.cjs#L8`](../../scripts/verify-package.cjs#L8)
- **事实与证据**：
  - [`scripts/verify-package.cjs`](../../scripts/verify-package.cjs#L8) 第 8 行直接使用动态导入：`const {extractFile}=await import('@electron/asar');`。
  - 但在 [`package.json`](../../package.json#L20-L29) 中，`devDependencies` 和 `dependencies` 均未声明 `@electron/asar`。该模块仅作为 `@electron/packager` 或 `electron` 的隐式次级依赖存在。
- **最小复现**：
  - 在开启严格隔离依赖（如 `pnpm` 或使用 `--install-strategy=nested` 的 npm 环境）且未全局安装该模块的环境中运行 `node scripts/verify-package.cjs <CandidateDir>`，将抛出 `ERR_MODULE_NOT_FOUND`。
- **建议**：
  - 在 [`package.json`](../../package.json#L20-L29) 的 `devDependencies` 中显式添加 `@electron/asar`，消除幽灵依赖。

---

### 2. [低危 / i18n] 英文语言环境下窗口原生标题（Window Title）未同步本地化
- **文件与行号**：
  - [`index.html#L7`](../../index.html#L7)
  - [`electron/main.cjs#L12`](../../electron/main.cjs#L12)
  - [`src/main.tsx#L5-L8`](../../src/main.tsx#L5-L8)
- **事实与证据**：
  - [`index.html#L7`](../../index.html#L7) 硬编码 `<title>模块化工作站 · 技术原型</title>`；[`electron/main.cjs#L12`](../../electron/main.cjs#L12) 窗口初始标题同样为 `'模块化工作站 · 技术原型'`。
  - [`src/main.tsx#L5`](../../src/main.tsx#L5) 仅根据 `navigator.language` 设置了 `document.documentElement.lang`，但整个渲染进程并未动态更新 `document.title`。
  - 尽管 [`src/i18n.ts#L27`](../../src/i18n.ts#L27) 中已具备 `appName: 'Modular Workstation'` 与 `prototype: 'Technical prototype'` 英文资源，但在英文系统环境下，Windows 原生标题栏仍显示中文。
- **最小复现**：
  - 启动应用并将 `navigator.language` 设为 `en-US`，界面内各模块文案成功切换为英文，但窗口原生标题栏依旧显示“模块化工作站 · 技术原型”。
- **建议**：
  - 在 [`src/main.tsx`](../../src/main.tsx#L5) 初始化渲染逻辑中，加入 `document.title = `${messages.appName} · ${messages.prototype}`;`。

### 3. [低危 / 无障碍 a11y] 非交互容器包含 `aria-label` 但缺乏对应语义 Role
- **文件与行号**：
  - [`src/App.tsx#L27`](../../src/App.tsx#L27)
- **事实与证据**：
  - 顶栏搜索占位区为：`<div className="search-surface" aria-label={messages.searchUnavailable}><Icon name="search"/><span>{messages.searchUnavailable}</span></div>`。
  - 普通 generic `<div>` 挂载 `aria-label` 却无 `role`（如未标注 `role="status"` 或 `role="region"`）时，符合标准的读屏软件（如 NVDA / Narrator）通常会忽略该容器标签。容器内虽有 `<span>` 可见文本供朗读，但该 `aria-label` 属性属于不规范写法。
- **最小复现**：
  - 运行 AXE / Lighthouse 等可访问性审查工具扫描顶栏，该节点会触发“Generic elements must not have an aria-label”警告。
- **建议**：
  - 移除无 role 容器上的冗余 `aria-label`，直接依赖内部可视 `span` 文本即可。

---

### 4. [低危 / 无障碍 a11y] 侧边栏与主区域标题层级在 DOM 顺序上存在逆序
- **文件与行号**：
  - [`src/App.tsx#L21`](../../src/App.tsx#L21)
  - [`src/App.tsx#L29`](../../src/App.tsx#L29)
- **事实与证据**：
  - 侧边栏位于 DOM 前部，使用了 `<h2>{page==='home'?messages.myStation:current.label}</h2>`（行 21）；而主内容区的主标题 `<h1 id="page-title">{current.title}</h1>` 出现在其后的行 29。
  - 在无障碍大纲导航中，屏幕阅读器按 DOM 顺序读取时，会在进入整页主标题 `H1` 之前先解析到子级 `H2`。
- **建议**：
  - 保持视觉样式不变的情况下，可将侧边栏小标题转为带适当 ARIA 属性的无语义标题或视觉辅助标签，确保页面主标题 `H1` 为整个文档大纲的首要层级。
