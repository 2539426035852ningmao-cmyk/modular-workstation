# 桌面界面基础规范（候选 V0.1）

关联：[Issue #10](https://github.com/2539426035852ningmao-cmyk/modular-workstation/issues/10)。项目所有者已在三版首页方向图中选择 **B：轻量模块** 作为初始视觉基线。本文件是首版可运行 Shell 正在使用的设计规范，最终品牌细节仍待后续审美验收。参考成熟系统设计规范的分类颗粒度，但视觉身份由本项目自行建立。

## 视觉方向与信息层级

工作站面向长期使用的专业桌面场景。固定导航、工作区内容与即时状态各占稳定位置；尽量让选中内容突出，其余界面保持安静。B 方向以清浅中性色和克制的青绿强调色为主，深色主题沿用同一语义层级。模块化四格标记只作轻量识别，不代表最终品牌。避免大型装饰渐变和占据工作区域的展示卡片。

## 可执行 Tokens

唯一 CSS 来源为 [`src/tokens.css`](../src/tokens.css)，Shell 的实现见 [`src/styles.css`](../src/styles.css)。新组件优先复用 token，不在组件内另设颜色或间距体系。

| 类别 | 当前约定 | 使用位置 |
| --- | --- | --- |
| 背景与表面 | `--color-bg`、`--color-sidebar`、`--color-surface`、`--color-border` | 工作区域、导航、空状态、分隔线 |
| 文字层级 | `--color-text`、`--color-muted`、`--color-subtle` | 标题、说明、次要状态；小字也须可读 |
| 强调与反馈 | `--color-accent`、`--color-selected`、`--color-selected-border`、`--color-success` | 当前页、键盘焦点和本地状态 |
| 字体 | Segoe UI → Microsoft YaHei UI；11/12/14/29 px | Windows 优先，中文与英文共用层级 |
| 间距 | 4/8/12/16/20/24/32 px | 控件内边距、分组、页面留白 |
| 圆角 | 4/6/8 px | 标记、导航、区域容器；避免过度圆润 |
| 控件尺寸 | 导航项至少 42 px 高；侧栏 224 px | 鼠标与键盘操作 |
| 图标语言 | 当前仅四格品牌记号和编号导航，线宽一致 | 避免混用 emoji/多套图标库；后续统一图标组件再引入 |

## 深浅主题与对比

默认跟随 Windows 系统主题，两个主题使用同名语义 token。候选文本对比已按 WCAG 相对亮度公式检查：主文字在背景上约 14.52:1（深）/13.33:1（浅）；次文字约 8.60:1/4.75:1；最弱的小字在侧栏上约 7.09:1/4.64:1。完整视觉与高对比模式仍需后续用户体验验收。

## 状态与交互

- 导航状态：默认、悬停、选中、键盘焦点。选中项有背景、边框和 `aria-current="page"`；焦点显示 2 px 轮廓，不能只靠颜色。
- 四个入口是真实可切换页面；尚无业务能力的页面显示明确空状态，不放无效的“创建”按钮。加载和错误状态随真实异步功能引入时再定义，不能用假数据模拟。
- 鼠标点击和键盘 Tab/Enter 使用同一语义按钮。侧栏收窄后保留可访问名称，避免只显示编号而失去读屏标签。
- 主内容区域保留可见标题与语义 `main`；导航使用 `nav` 标签及名称。页面不自动播放装饰动画。

## Windows 缩放与最小窗口

窗口最小物理尺寸 800×540。CSS viewport 宽度不高于 700 px 时侧栏压缩到 64 px，显示编号并保留每个按钮的 `aria-label`；标题、导航和空状态保持可读。自动化对 200% Electron 缩放检查水平溢出；更高缩放、高对比模式、屏幕阅读器和多显示器 DPI 切换需要后续实测。

## 后续审美决策

本次确定 B 方向及能被代码使用的基础规范。项目所有者在看到真实窗口后仍可修改：整体密度、青绿强调色、品牌标记、字体层级、深浅主题细节。S1 高保真页面和插件 UI 规范以此为起点继续推进，不把本原型当成完整设计系统验收。
