## 核心理解与长期使用

用户偏好轻量、扎实、稳重、精致的个人工作站：用统一实色和面型图标建立确定感，用轻边框、克制层次和短文案减少干扰。首页保持容易理解，专业复杂度按工作区需要展开。

本文件是本项目可版本化的长期设计记忆，后续会话通过仓库恢复，不依赖代理自行回忆。它不能保证其他仓库或未读取本文件的会话自动继承偏好。设计记录见 PR #19，运行修订与本轮方法整理见 [PR #20](https://github.com/2539426035852ningmao-cmyk/modular-workstation/pull/20)。

### 判断依据的顺序

1. 新的明确用户反馈优先于旧稿；同一属性变更时保留否定原因，标清当前基线，不把历史配色混在一起。
2. 区分已确认偏好、实现参数和候选建议。下表风格与配色方向来自用户确认；650/400 字重、14px 内边距、边框 50% 等为当前实现基线，可按显示效果细调，不表示用户锁死全部数值。
3. 先核对本表、当前运行时 Token、实际截图与相关 PR；旧 D1/D2 候选不能覆盖新反馈。PR 未合并时直接读取实施分支。
4. 局部认可不代表全部页面、产品阶段或架构选型已验收。已确定事项不重复询问；只有新的实质歧义才需要澄清。

## 可复用的分析与制作方法

### 先理解截图表达的目的

- 定位用户框出的对象和当前状态，再判断属于层级、填色、边界、图标、文案还是交互问题。红绿蓝标注用于定位，不是产品配色要求。
- 将感受转成可检查的改变：“虚浮”先检查面型比例和选中填色；“抢眼”先检查边框亮度与透明度；“脏”先检查灰度和色相，不一味降低饱和度。
- 分开检查色相、饱和度和明度，有依据地微调。警告保持干净红色相，避免从刺眼直接滑到灰脏；确实不确定的颜色才提供小样。
- “扎实”靠明确实色、统一图标块和轻微受光层次表达，不靠粗描边、厚阴影或给所有元素加深色。
- 分清导航与选择：点击跳转的卡片不能默认高亮；真实选择、悬停、按下和焦点分别表达。

### 再按层级制作

1. 保留稳定导航和业务边界，先处理信息顺序与冗余区域，再处理颜色、图标、字重和细节，不借局部反馈重做前端。
2. 横向信息左侧重点、右侧较轻；真实选中与当前操作有强调，普通卡片一致，辅助说明退后。
3. 优先修改共享 Token 与组件，扫描同类位置及深浅主题，避免只修截图一处。图标面型、圆角、尺寸和导向提示保持统一。
4. 文案逐项减负：短、直接，注释与占位不用标点，不加入冗长开发说明；保留真实能力边界。此规则不要求代码、文档或用户内容去掉标点。
5. 每轮聚焦当前反馈，做可回滚的小修改；自主修正相邻一致性问题，不扩大为组件库切换或未排期功能。

### 常见反例与正确方向

| 不再重复的做法 | 应采用的方向 |
| --- | --- |
| 空心图标与淡底细框表现所有状态 | 面型为主 实色表达真实选中 |
| 默认把中间模块卡做成蓝色突出 | 三卡常规一致 真实选择后才整卡强调 |
| 每个选中控件另配一种蓝 | 同主题共用强调 Token |
| 边框太亮就降低整个控件透明度 | 只减轻装饰边框 保持文字和焦点清楚 |
| 红色过亮后调成偏灰暗红 | 保持干净红色相 轻调饱和度与明度 |
| 右侧文字比左侧更粗 | 左重右轻 |
| 长句和开发注释填满空白 | 简短真实的辅助短语 |
| 带尾部箭杆的完整箭头 | 留边距的圆角直角提示 |
| 复制参考产品或随意新增装饰区 | 提炼氛围与结构 沿用轻量首页 |

## 每次视觉修改交付前复查

- 对照本次截图指出的区域，确认修改来自共用样式，没有只修单张截图。
- 检查深浅主题、普通/选中/键盘焦点与窄窗口；文本仍清楚，填色没有侵入业务内容。
- 检查左重右轻、短文案无标点、圆角直角无箭杆，以及同类卡片普通状态一致，不能只检查颜色。
- 更新受影响的运行截图或设计预览，按改动执行对应验证；交付运行候选时核验实际便携包。不得将静态设计验证写成业务功能已实现，不重复运行与改动无关的检查。
- 将新的明确反馈同步到本表、D1 和相关修订记录；先查现有记录，不重复向用户确认已决定的偏好。
- 交接时区分确认方向、实现能力、实际测试与待验收项；记录分支、PR 和回滚入口，保留旧候选。
