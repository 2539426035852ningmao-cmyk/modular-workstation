# 开发路线图（ROADMAP）
版本：V0.1｜2026-10-19｜时间估计暂不承诺（先完成技术原型）

## 项目运营规则
- GitHub Issues = 每项任务的目标、依赖、验收、实施记录。
- GitHub Projects「模块化工作站 · 开发总控」= 任务状态与工作队列。
- PROJECT_STATE.md = 可恢复的简短上下文快照（引用 Issue/PR，不能取代实时看板）。
- 当期最多一个唯一主任务。任务插队需明确原因、记录影响，并更新看板。
- 关卡未通过，不宣布阶段完成；发现高风险安全/数据问题可主动阻断当前开发。

## 关键阶段与门槛

### S0 项目治理与开发总控（当前）
交付：仓库、关联看板、产品基线、路线图、状态快照、AI 协作规则、完成定义、决策日志、Issue/PR 模板、CI 规划。
门槛：新会话可仅凭仓库及看板回答“当前做什么、谁负责、下一个任务是什么”；通过至少一次任务→PR→验收的实操演练。
当前唯一主任务：[S0-01](https://github.com/2539426035852ningmao-cmyk/modular-workstation/issues/1)。

### S1 产品信息架构与高保真视觉标准
交付：导航信息架构、页面状态流、品牌探索、深浅主题 Token、基础组件规范、核心六页面设计与交互说明。
门槛：关键页面均有明确真实操作路径、异常状态与可落地组件设计；获得产品所有者审美确认。

### S2 工作站 Shell 可用版本
交付：Windows 应用骨架、全局导航、标签、工作区、面板、主题、i18n、设置、搜索命令入口与任务状态框架。
门槛：离线可启动、完成基础工作区操作、布局持久化、双主题交互检查、E2E 测试。

### S3 插件 SDK、隔离与生命周期 MVP
交付：清单规范、SDK、受限插件执行环境、权限服务、注册/激活/禁用/卸载/升级、开发模板与插件验证器。
门槛：不编辑主程序源码即可安装并运行独立示范插件；危险系统调用不被无授权插件获得；崩溃不拖垮主程序。若不能满足，阻断后续插件扩张。

### S4 官方文件与素材管理插件
交付：原位关联与导入双模式、后台索引、搜索、缩略图、预览、基础批量操作、属性面板、文件异常恢复。
门槛：真实文件可完成端到端测试；移除引用与删除文件明确分离；文件失联、权限错误、取消任务可恢复。

### S5 首个公开测试版与发布质量
交付：持续集成、版本策略、安装与升级、异常恢复、兼容与性能报告、开源贡献及发布文档。
门槛：发布检查通过，用户批准发布；不把 PR 已合并等同于产品体验验收。

### S6 长期生态
交付：统一 AI 模型服务、跨插件工作流、插件目录与审查、更多官方插件、内置 AI 插件开发中心。
门槛：独立 API 版本管理、安全与数据隔离测试、实际插件复用验证。

## 依赖与变更
顺序：S0 → S1（含桌面技术/安全验证原型）→ S2 → S3 → S4 → S5 → S6。
S1 的技术验证允许并行少量探索，不代表可以提前跳过 S0 正式构建业务。
技术栈候选：Electron + React + TypeScript；Tauri 作为对照候选。尚未通过插件隔离、性能、打包与权限验证，不能标记为最终锁定。
