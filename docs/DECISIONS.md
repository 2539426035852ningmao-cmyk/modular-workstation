## ADR-001 统一的项目事实来源
日期：2026-10-19｜状态：Accepted
- 决定：需求范围以 docs/PRODUCT.md 为基线；实施任务、状态和审查信息以 GitHub Issues/Projects/PR 为准；PROJECT_STATE.md 是恢复入口与快照；架构决策记录此文件。
- 原因：避免多个 AI 因跨会话上下文不同造成计划漂移。
- 影响：提交完成需更新相关任务与必要文档；不得同时维护彼此冲突的任务状态。

## ADR-002 面向 Windows 的本地优先模块化工作站
日期：2026-10-19｜状态：Accepted
- 决定：Windows 桌面优先、离线工作、本地数据为主，插件按需启用；深浅双主题与统一工作空间。
- 原因：兼顾广泛用户、专业体验、模块化扩展。
- 影响：云端与 AI 不可成为启动基础能力的硬依赖。

## ADR-003 插件安全等级与用户授权
日期：2026-10-19｜状态：Accepted（实现方式未定）
- 决定：普通插件默认受限；高权限扩展必须显式授权，官方/审核来源不能绕开最小权限；完整授权明确提示风险。
- 风险：独立进程不等于 OS 安全沙盒。必须实测恶意/错误插件行为并处理系统边界。
- 影响：插件动态安装不得绕过授权或加载到主进程高权限上下文。

## ADR-004 AI 优先的开发组织
日期：2026-10-19｜状态：Accepted
- 决定：ChatGPT 组织产品与任务协调；Codex 主开发；Gemini 独立复核；用户把关审美与关键审批。
- 影响：共用产品规范、验收与项目记录；AI 审查不是自动安全认证。

## ADR-005 桌面框架与插件底座
日期：2026-10-19｜状态：Proposed，未决
- 候选：Electron + React + TypeScript；对比 Tauri 2。
- 评估：动态安装受限插件、执行权限边界、Windows 打包、启动和空闲内存、UI 插件一致性、AI 编程可维护性。
- 不得将候选框架描述为最终定论。

## ADR-006 开源许可证
日期：2026-10-19｜状态：Accepted for initial repository, review before release
- 决定：仓库当前采用 Apache License 2.0；主程序与官方插件免费开源；第三方插件可开源/闭源、免费/收费。
- 条件：发布前完成依赖许可证及分发合规审查。

## ADR-007 桌面 Shell 候选原型
日期：2026-10-19｜状态：Proposed，未决

- 背景：项目所有者要求先交付能启动的桌面窗口与基础导航；S0 的 #4/#5 和 S1 设计关卡尚未验收。
- 决定：在 [Issue #10](https://github.com/2539426035852ningmao-cmyk/modular-workstation/issues/10) 中以 Electron + React + TypeScript 实施可逆技术原型，验证 Windows 本地窗口、导航、离线运行与基本权限设置；不把它视为正式框架定案。
- 备选：Tauri 2 仍需独立原型对照；本机目前没有 Rust 工具链。成熟模板可参考，但本任务只需最小 Shell，避免引入未使用的插件、路由和发布体系。
- 影响和风险：Electron 便携目录较大；动态插件隔离、启动/内存指标、安装与更新、安全评估均待后续实测。此原型不得承载未经授权的第三方代码。
- 复核条件：S1 对照 Electron/Tauri 的 Windows 打包、插件权限边界、启动和空闲内存，并经项目所有者确认后再决定正式框架。

## ADR-008 首页初始视觉方向
日期：2026-10-19｜状态：Accepted for initial Shell，细节可迭代

- 背景：项目所有者要求从项目初期建立细分的设计规范，并要求三版首页高保真方向图。
- 决定：三版对照后由项目所有者选择 **B：轻量模块** 作为首版 Shell 首页视觉基线。首版采用清浅中性色、青绿强调、固定导航、模块卡片和明确空状态；深色主题使用相同语义 token。
- 备选：A 专业工作台信息更密，C 内容优先多面板结构适合后续专业工作区。两者保留作为布局与密度参考，不作为本次首页实现目标。
- 影响和风险：当前只有视觉和导航骨架，图中创建工作区等入口尚未实现；B 的具体品牌细节、图标和高保真组件仍需用户验收。禁止将概念图的按钮误报为真实功能。
- 复核条件：用户体验可运行窗口后继续微调；S1 设计系统审查和技术关卡仍需单独完成。
