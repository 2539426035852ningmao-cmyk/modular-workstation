# 质量关卡与任务完成定义（QUALITY_GATES）
版本：V0.1｜2026-10-19

## 一、Issue 任务模板要求
- 背景、目标、非目标；依赖的 Issue/ADR；影响的模块及安全/数据风险。
- 明确的验收条件：可由他人重复操作验证、区分已有功能与目标功能。
- 对应设计或 API 规范；测试计划和交付证据。
- 实施者不得自行扩大需求。新增需求另建 Issue，阻塞问题明确升级。

## 二、PR 完成定义（DoD）
- [ ] 与 Issue 范围一致；列出修改文件、设计或架构影响。
- [ ] 构建、类型检查、静态检查与适用测试通过（未接入 CI 前显式标注未执行）。
- [ ] UI 变化：深浅主题、空态、加载、失败、键盘操作、合理窗口尺寸已验证。
- [ ] 插件变化：权限声明、异常隔离、API 版本、兼容性/卸载/升级路径已核查。
- [ ] 文件变化：不丢失用户数据；删除、移动、备份、失败回滚有策略。
- [ ] 提供实际截图/日志/测试结果，不使用“应该能用”代替证据。
- [ ] 更新必要文档与关联 Issue/PR，描述剩余风险。
- [ ] 合并与发布遵循分支保护及用户指定的审批条件。

## 三、阶段关卡
- S0：治理文档与看板联动可用，至少一个完整任务→PR→审查演练。
- S1：高保真信息架构与设计系统有审美确认；候选技术经过可复现原型测试。
- S2：离线 Shell 真实运行；工作区布局保存恢复、双主题与常规键盘导航正常。
- S3：动态示范插件安装与隔离成功；禁止普通插件绕过权限；错误恢复有效。
- S4：真实文件管理与搜索可用；误删防护与失联恢复经过验证。
- S5：Windows 安装、升级、卸载、迁移、性能、安全及开源发布检查通过。

## 四、验收职责
- Codex：实施、运行并附上可重现测试证据。
- Gemini：独立复核设计风险、代码与测试覆盖，可提出缺陷但不得自行决定通过。
- ChatGPT：核对需求、阶段关卡与证据，给出通过/阻塞建议。
- 用户：最终体验验收与重要方案/发布审批。

## 五、严格禁止
- 未执行测试却宣称通过。
- 将占位按钮/模拟数据视为最终功能。
- 用授权弹窗代替真正的权限隔离。
- 绕过 PR/任务管理直接改写主分支大量功能。
- 未记录原因而推翻已批准的产品需求、设计系统或架构边界。
