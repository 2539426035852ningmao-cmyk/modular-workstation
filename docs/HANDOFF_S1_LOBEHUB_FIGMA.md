## 2. 视觉与布局必须分开理解

### 2.1 LobeHub：借鉴视觉语言，不照搬页面
目标关键词：**清晰、温润、克制、有秩序、优雅、轻量、现代、专业但不冰冷**。
- 中性表面和细腻的层级（背景 / 二级表面 / 浮层 / 选中与悬停）
- 语义化 Design Token，统一深浅主题，不在组件里散布硬编码颜色
- 稳定的字体层级、适当留白、克制的 4px 基础间距和圆角
- 精致且有一致线宽的图标，短促、可关闭的功能动效
- 所有交互元素具有明确默认、悬停、按下、选中、禁用、焦点、加载、空态、失败等状态
- 避免玻璃拟态滥用、无意义大渐变、超大欢迎卡片、营销风仪表盘和过度装饰

Lobe UI 可作为**组件库候选与参考**，不是已决定的技术依赖。若考虑引入，先提交与现有 React/Vite/Electron、主题实现、现有组件、包体积及许可的对比评估；不得直接全面替换。

参考：
- https://github.com/lobehub/lobehub
- https://ui.lobehub.com/

### 2.2 Figma：借鉴专业工作台空间组织，不照搬设计编辑器
目标为固定的 **Application Shell + 可切换 Workspace 模板**：
- **全局导航 Rail**：产品级入口、工作空间切换、个人设置等；一直稳定存在，但可收窄。
- **上下文侧栏**：随页面显示文件树、项目列表、插件分组或资源分类；可以折叠、适度调整宽度。
- **中央工作区**：视觉与操作重心，承载页面、标签、画布、文件网格/列表和插件独立界面。
- **右侧 Inspector**：仅在有选中对象或专业编辑任务时出现；详情、属性、操作和插件参数；可折叠。
- **顶部栏**：路径/面包屑、工作区标签、搜索/命令、上下文工具栏；减少功能重复。
- **状态 / 任务区**：文件扫描、导入、插件运行、错误提醒等信息，默认紧凑、按需展开。

应参考 Figma 的空间划分和可预测操作，而非逐像素复制它的图标、品牌、专属编辑控件。

参考：
- https://www.figma.com/
- https://help.figma.com/

## 3. 页面模板不得一刀切

| 页面模板 | 核心结构 | 设计原则 |
|---|---|---|
| 首页 Home | 固定外壳 + 轻量模块卡片 + 最近项目/入口 | **保留 B「轻量模块」作为首页基线**，不默认塞入左右双侧专业面板 |
| 专业工作区 Workspace | Rail + 资源侧栏 + 中央工作区/标签 + 可选 Inspector + 状态区 | 参考 Figma，可调整布局且保持统一主框架 |
| 插件中心 Plugins | 固定外壳 + 分类/搜索 + 插件列表/详情/权限视图 | 接近成熟软件商店，不使用假按钮或伪安装状态 |
| 文件素材工作区 Assets（未来官方插件） | 文件树 + 中央缩略图/列表 + 详情/预览 + 操作状态 | 验证可复用的专业 Workspace 模板；文件原位置关联与复制导入分开 |
| 设置 Settings | 固定外壳 + 设置分组 + 表单内容 | 优先可读性、易查找、明确恢复默认；无须硬套 Inspector |

注意：尚未实现的功能继续用诚实空态表示，不因画出 UI 就声称可用。

## 4. 候选布局数值（仅用于第一轮设计稿和原型）

下表是**候选**，不是像素级已批准标准：

| 区域 / 参数 | 候选范围 |
|---|---|
| 全局导航 Rail | 52–56px |
| 上下文侧栏 | 220–280px，支持折叠和受限缩放 |
| 顶栏 | 44–48px |
| Inspector | 280–320px，按需显示/隐藏 |
| 底部状态条 | 24–28px |
| 普通正文 / 辅助说明 | 14px / 12px |
| 常用控件高度 | 32–36px（具体按 Windows 可用性验证） |
| 间距 | 4/8/12/16/24/32px 基础序列 |
| 圆角 | 常规 6–8px；弹窗 10–12px，按组件角色调整 |
| 动画 | 大致 100–200ms；尊重减少动态效果偏好 |

窗口至少在 1920×1080、1366×768、系统缩放 125%/150%/200% 下检查，并留足中央区域。不是所有面板都应该始终可见；优先折叠非核心区域。

## 5. 当前实现与目标之间的差异

当前来源：`src/App.tsx`、`src/styles.css`、`src/tokens.css`、`docs/DESIGN_FOUNDATIONS.md`；如仓库已变化，请以最新实际源码为准。

| 当前真实状态 | 设计目标 |
|---|---|
| 一个约 224px 的整体侧栏 | 拆为应用级 Rail 与可变上下文侧栏 |
| 中央单页内容 | 根据页面模板提供标签/工具栏/中央工作区 |
| 未实现 Inspector | 专业页面按需出现，可折叠，不强制首页显示 |
| 首页 B 模块卡片已存在 | 保留方向，提升 LobeHub 式字体、留白、图标、状态精度 |
| 初步深浅主题 Token 已存在 | 扩展表面、边界、文本、交互、状态与密度等语义 Token |
| 工作区/插件/设置是可切换的诚实空态 | 先设计好模板和交互状态，再按后续独立任务实现真实业务 |
| 仍没有插件运行时 | 不在本设计任务中擅自实现插件系统 |

已有 Electron 权限防护、离线基线、键盘导航等不得被纯视觉改造破坏。

## 6. 这一轮设计任务的明确交付顺序

**D0 · 审计**：读取最新源码和 Issue，列出保留项、差距、可能破坏的已通过测试。校验当前唯一主任务是否允许开始设计施工。

**D1 · 设计架构提案（先做，不改业务代码）**：
- Home / Workspace / Plugins 三种页面模板和导航状态流
- 主框架区域尺寸、折叠、横向溢出和缩放适配
- 深浅主题 Token、文字、间距、控件与状态体系
- 通用组件清单、插件 UI 适配边界
- 初步视觉基准：LobeHub 精致视觉 × Figma 工作区结构 × B 轻量首页

**D2 · 高保真确认**：先提供至少首页、专业工作区/素材管理、插件中心三类高保真页面（含深色基准、适用时浅色），让用户确认设计；**不能仅凭文本提案宣称视觉已经通过**。图片/设计源可由合适的设计工具创建，Codex 负责对照代码落地说明。

**D3 · 实现（需获得授权后）**：在既有 React/Electron 工程按组件逐步替换，设计 Token 优先，保留主框架与可访问性；每个 PR 小范围修改，提供截图与实际测试证据。

**D4 · 视觉回归与项目交接**：核对像素层级、交互状态、深浅主题、缩放、导航回归；更新 DESIGN_FOUNDATIONS 与 ADR、Issue 进度。回报“下一项唯一任务”。

如果用户只要求读档同步，停在 D0–D1，不要擅自执行 D3。
